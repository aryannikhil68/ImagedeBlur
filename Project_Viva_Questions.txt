CATEGORY A: BASIC IMAGE PROCESSING QUESTIONS
--------------------------------------------------------------------------------

Q1: What is image deblurring?
Answer:
Image deblurring is an image restoration process that recovers a sharp, clear, and high-fidelity image from a blurry or degraded observation, reversing the smearing effects caused by camera shake, object motion, or optical defocus.

Q2: What is the mathematical formulation of image degradation?
Answer:
B = (I * K) + N
Where:
- B is the degraded/blurry image.
- I is the true sharp image.
- K is the blur kernel (Point Spread Function / PSF).
- * represents 2D mathematical convolution.
- N is additive camera sensor noise.

Q3: Why is image deblurring called an "ill-posed inverse problem"?
Answer:
According to Jacques Hadamard, a problem is well-posed if a solution exists, is unique, and depends continuously on initial conditions. Deblurring violates this because:
1. Multiple sharp images can produce the exact same blurry image (non-unique).
2. High-frequency details are lost during blur convolution (information loss).
3. Naive inversion divides by near-zero frequencies, which explodes sensor noise (unstable).

Q4: What is the difference between image denoising and image deblurring?
Answer:
- Denoising removes high-frequency, uncorrelated additive noise (such as sensor grain or salt-and-pepper noise) while preserving edges.
- Deblurring restores high-frequency structural edges that were smoothed out and smeared across neighboring pixels by convolution with a blur kernel.

Q5: What is the difference between blind and non-blind deblurring?
Answer:
- Non-blind deblurring assumes the blur kernel (K) is known in advance and only attempts to solve for the sharp image (I).
- Blind deblurring assumes the blur kernel is completely unknown, which is the realistic real-world case. Our deep learning model performs blind deblurring because it restores images directly without needing the kernel.

Q6: What is a Point Spread Function (PSF)?
Answer:
The Point Spread Function (PSF) describes the impulse response of an optical imaging system. It represents how a single, infinitely sharp point of light in the 3D world is spread across neighboring 2D pixels on the camera sensor due to motion or defocus.

CATEGORY B: DEEP LEARNING FUNDAMENTALS
--------------------------------------------------------------------------------

Q7: How does deep learning restore an image without calculating the blur kernel?
Answer:
Deep neural networks act as universal function approximators. Instead of explicitly calculating the mathematical kernel K and inverting it, the network learns an end-to-end non-linear mapping function f_theta(B) -> I by learning natural image priors, edge statistics, and multi-scale feature correlations directly from paired training data.

Q8: What is an activation function, and why is it necessary?
Answer:
An activation function introduces non-linearity into the network. Without non-linear activation functions, stacking multiple convolutional layers would merely result in a single linear transformation (matrix multiplication), making it impossible for the network to learn complex deblurring mappings.

Q9: What is PReLU (Parametric Rectified Linear Unit), and why did we choose it over standard ReLU?
Answer:
PReLU is defined as f(x) = max(0, x) + a * min(0, x), where 'a' is a learnable parameter. Unlike standard ReLU, which completely zeros out negative values (causing the "dying ReLU" problem where neurons stop updating), PReLU allows a small learnable negative gradient, preserving gradient flow in subtle pixel difference regions.

Q10: What is Backpropagation?
Answer:
Backpropagation is the algorithm used to train neural networks. It applies the mathematical chain rule of calculus to calculate the partial derivatives (gradients) of the loss function with respect to every weight in the network, propagating the error backwards from the output layer to the input layer.

Q11: What is Overfitting, and how did we prevent it?
Answer:
Overfitting occurs when a neural network memorizes training samples but fails to generalize to unseen test images. We prevented overfitting by:
1. Using synchronized data augmentation (horizontal and vertical flips).
2. Applying weight decay (L2 regularization) of 1e-5 in the Adam optimizer.
3. Incorporating Batch Normalization layers.
4. Using an independent validation split with early checkpointing.

Q12: What is Gradient Descent, and how does learning rate affect it?
Answer:
Gradient Descent updates model weights in the direction opposite to the gradient of the loss function: W_new = W_old - lr * dLoss/dW. The learning rate (lr) controls step size. If too large, training diverges; if too small, convergence is painfully slow. We used lr = 1e-3 with an adaptive scheduler.

CATEGORY C: CNN AND NEURAL NETWORK ARCHITECTURE
--------------------------------------------------------------------------------

Q13: What is a Convolutional Neural Network (CNN)?
Answer:
A CNN is a specialized deep learning architecture designed for grid-structured data like images. Instead of using fully connected layers, CNNs use small learnable filters (kernels) that slide across the image, exploiting spatial locality and translation invariance while drastically reducing parameter count.

Q14: What is a convolution operation in CNNs?
Answer:
In a 2D convolution, a small weight matrix (e.g., 3x3) performs element-wise multiplication with an underlying image patch, sums the values, adds a bias term, and outputs a single scalar value in the resulting feature map.

Q15: What is the purpose of Stride and Padding in convolution?
Answer:
- Stride: The step size the kernel moves across the image. Stride=1 preserves spatial dimensions; Stride=2 downsamples the feature map by half.
- Padding: Adding extra border pixels (usually zeros). Padding=1 with a 3x3 kernel and Stride=1 ensures the output spatial dimensions exactly match the input dimensions (Same padding).

Q16: What is a Residual Block, and how does it work?
Answer:
Introduced by He et al. (ResNet), a residual block uses a shortcut/skip connection where the input is added directly to the output of convolutional layers: Output = x + F(x). The network only needs to learn the residual correction F(x) rather than the complete image, preventing vanishing gradients.

Q17: What is Transposed Convolution (ConvTranspose2d)?
Answer:
Transposed Convolution (sometimes called deconvolution or fractionally-strided convolution) is an upsampling layer. It uses learnable weights to expand lower-resolution feature maps back to higher spatial dimensions, allowing the decoder to reconstruct the full-resolution image.

Q18: What is the exact architecture and parameter count of DeblurNet-Lite?
Answer:
DeblurNet-Lite has exactly 293,642 trainable parameters. It consists of:
1. Input Encoder: Conv3x3 (3 -> 32 channels) + PReLU.
2. Downsampler: Conv3x3 (32 -> 64 channels, stride 2) + BatchNorm + PReLU.
3. Bottleneck: 3 stacked Residual Blocks (64 channels each).
4. Upsampler: ConvTranspose2d (64 -> 32 channels, stride 2) + BatchNorm + PReLU.
5. Skip Fusion: High-resolution skip connection concatenating early 32-channel features with upsampled 32-channel features (64 -> 32 channels).
6. Reconstruction: Conv3x3 (32 -> 3 channels) + Sigmoid activation.

CATEGORY D: DATASET AND PREPROCESSING
--------------------------------------------------------------------------------

Q19: What is a paired image dataset in image restoration?
Answer:
A paired dataset consists of matching image tuples (X, Y), where X is the degraded/blurry image and Y is the corresponding clean/sharp ground truth of the exact same scene, aligned pixel-for-pixel.

Q20: How many samples did we use, and what is our train/val/test split?
Answer:
We used 300 strictly paired image scenes:
- Training: 240 pairs (80%)
- Validation: 30 pairs (10%)
- Testing: 30 pairs (10%)

Q21: What is "Data Leakage," and how did we prevent it?
Answer:
Data leakage happens when information from the test or validation set leaks into the training pipeline, giving artificially high performance. We strictly partitioned unique scene IDs into train, val, and test groups BEFORE any blur convolution was applied, ensuring no identical scene exists across splits.

Q22: Why did we resize images to 128x128 pixels?
Answer:
Resizing to 128x128 pixels maintains essential edge and texture structures while keeping tensor memory consumption under 400 MB RAM during training, allowing smooth execution on a 4 GB RAM laptop without CPU thrashing or memory crashes.

Q23: Why is normalization required (dividing pixel values by 255.0)?
Answer:
Raw digital image pixels range from 0 to 255. Feeding unnormalized values into a neural network causes large activations, which lead to exploding gradients during backpropagation and unstable training. Normalizing to [0.0, 1.0] stabilizes gradient updates and speeds up convergence.

Q24: Why must data augmentation be synchronized for paired deblurring?
Answer:
In image classification, you can augment an image independently. But in image deblurring, every pixel in the blurry image corresponds to an exact pixel in the sharp ground truth. Therefore, geometric transforms (such as horizontal or vertical flips) must be applied identically to both images simultaneously to maintain strict spatial alignment.

CATEGORY E: MODEL TRAINING
--------------------------------------------------------------------------------

Q25: Did we use pretrained weights or train from scratch?
Answer:
We trained our model 100% from scratch using randomly initialized weights. No pretrained weights or downloaded models were used, fulfilling the core academic requirement of understanding how the neural network learns deblurring.

Q26: What weight initialization method was used?
Answer:
We used Kaiming (He) Normal Initialization (`torch.nn.init.kaiming_normal_`), which sets initial weights according to a normal distribution with variance scaled by 2/fan_in. This specifically prevents vanishing or exploding gradients when using PReLU activations.

Q27: What batch size was selected, and why?
Answer:
We selected a batch size of 4. On a CPU with 4 GB of RAM, smaller batch sizes prevent RAM exhaustion, provide regular stochastic gradient updates, and act as a mild regularizer to improve generalization.

Q28: What is an epoch?
Answer:
An epoch is one complete forward and backward pass of the entire training dataset through the neural network. In our project, 1 epoch equals 60 batches of 4 images each (240 training images).

Q29: How did we optimize training for a CPU-only laptop?
Answer:
1. Detected hardware using `torch.device("cpu")`.
2. Set `torch.set_num_threads(4)` to prevent thread contention.
3. Used small batch size (4) and compact resolution (128x128).
4. Set DataLoader `num_workers=0` to eliminate Windows multiprocessing overhead and paging.
5. Used a compact model (< 300K parameters) requiring < 400 MB RAM.

Q30: What is model checkpointing?
Answer:
Checkpointing saves the internal state dictionary (weights and biases) of the model during training. We saved `best_model.pth` whenever the validation loss reached a new minimum, ensuring we keep the best generalized model even if later epochs fluctuate.

CATEGORY F: LOSS FUNCTIONS AND OPTIMIZERS
--------------------------------------------------------------------------------

Q31: What loss function did we use, and what is its formula?
Answer:
We used L1 Loss (Mean Absolute Error):
L1 = (1 / N) * sum(|Y_predicted - Y_groundtruth|)
It computes the average absolute pixel-wise difference between the network's output and the true sharp image.

Q32: Why did we choose L1 Loss over L2 Loss (MSE)?
Answer:
L2 loss squares errors ((Y_pred - Y_true)^2), heavily penalizing large outliers. Because sharp edges have sharp pixel differences, L2 forces the network to play safe and output an average blur, producing smooth, blurry edges. L1 penalizes errors linearly, which preserves sharp boundaries, fine lines, and visual contrast.

Q33: What is the Adam optimizer, and why is it preferred over standard SGD?
Answer:
Adam (Adaptive Moment Estimation) combines the advantages of AdaGrad (which adapts learning rates based on past gradients) and RMSProp (which keeps an exponentially decaying average of squared gradients). It maintains individual adaptive learning rates for each parameter, providing faster and more stable convergence than basic Stochastic Gradient Descent.

Q34: What is Weight Decay, and why is it used?
Answer:
Weight decay is an L2 regularization technique that adds a small penalty proportional to the sum of squared weights to the loss function: Loss_total = Loss_L1 + lambda * sum(w^2). It discourages the network from learning unnecessarily large weights, preventing overfitting. We used weight decay = 1e-5.

Q35: What is a Learning Rate Scheduler?
Answer:
A learning rate scheduler dynamically adjusts the learning rate during training. We used `ReduceLROnPlateau(optimizer, mode='min', factor=0.5, patience=3)`, which monitors validation loss and cuts the learning rate in half if validation loss fails to decrease for 3 consecutive epochs.

Q36: Why do we call `optimizer.zero_grad()` before `loss.backward()`?
Answer:
In PyTorch, gradients accumulate by default on every `.backward()` call (they are added together rather than overwritten). If we do not call `optimizer.zero_grad()`, gradients from the previous batch would combine with the current batch, resulting in incorrect weight updates.

CATEGORY G: EVALUATION METRICS: PSNR AND SSIM
--------------------------------------------------------------------------------

Q37: What is PSNR, and what is its mathematical formula?
Answer:
PSNR stands for Peak Signal-to-Noise Ratio. It measures the ratio between the maximum possible power of a signal and the power of corrupting noise, expressed in decibels (dB):
PSNR = 10 * log10(MAX_I^2 / MSE)
Where MAX_I is the maximum possible pixel value (1.0 for normalized tensors), and MSE is Mean Squared Error:
MSE = (1 / (C * H * W)) * sum((Pred - Target)^2).

Q38: What do typical PSNR values indicate?
Answer:
- Below 20 dB: Noticeably blurry or degraded image.
- 20 dB to 25 dB: Moderate restoration; clear structural improvement.
- 26 dB to 32 dB: Good restoration quality; sharp edges and low noise.
- Above 35 dB: Visually indistinguishable from original.

Q39: What is SSIM, and how does it differ from PSNR?
Answer:
SSIM (Structural Similarity Index) was developed by Wang et al. (2004) to measure perceived visual quality. While PSNR only calculates numerical pixel errors without understanding structure, SSIM evaluates three distinct components of human visual perception:
1. Luminance comparison: l(x, y) = (2*mu_x*mu_y + c1) / (mu_x^2 + mu_y^2 + c1)
2. Contrast comparison: c(x, y) = (2*sigma_x*sigma_y + c2) / (sigma_x^2 + sigma_y^2 + c2)
3. Structural correlation: s(x, y) = (sigma_xy + c3) / (sigma_x*sigma_y + c3)
SSIM = [l(x, y)] * [c(x, y)] * [s(x, y)]
Range is [-1, 1], where 1.0 indicates perfect structural identity.

Q40: Can an image have high PSNR but poor visual quality?
Answer:
Yes! If an image is smoothed out (slightly blurred), its MSE can remain low, giving a deceptively high PSNR even though sharp textures and edges are completely gone. That is why SSIM is essential alongside PSNR: SSIM penalizes lost structural textures that PSNR might overlook.

Q41: What were our model's quantitative results on the test set?
Answer:
On 30 unseen test images:
- Baseline Blurry Image: PSNR = 19.71 dB | SSIM = 0.6934
- DeblurNet-Lite Restored: PSNR = 25.72 dB | SSIM = 0.9331
- Quantitative Improvement: +6.02 dB PSNR gain and +0.2397 SSIM gain (reaching 0.9331 structural fidelity).

Q42: What is the inference time of our model?
Answer:
Approximately 35 to 45 milliseconds per image on a standard CPU, meaning the model operates at nearly 25 to 30 frames per second for near-real-time restoration.

CATEGORY H: PYTORCH IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------

Q43: What is `torch.nn.Module`?
Answer:
`torch.nn.Module` is the base class for all neural network modules in PyTorch. Our custom `DeblurNetLite` class inherits from it. It automatically registers layers, parameters, handles submodules, and manages moving tensors between CPU and GPU.

Q44: What is the purpose of `model.train()` and `model.eval()`?
Answer:
- `model.train()` sets the network into training mode. In this mode, layers like BatchNorm update running mean and variance, and Dropout drops neurons.
- `model.eval()` sets the network into evaluation/inference mode. In this mode, BatchNorm uses frozen running statistics, and Dropout is disabled, ensuring deterministic outputs.

Q45: What does `with torch.no_grad():` do?
Answer:
`torch.no_grad()` is a context manager that disables the PyTorch autograd engine. When evaluating or running inference, we do not need to calculate gradients. Disabling gradient tracking drastically reduces memory consumption and speeds up computation.

Q46: Why is Sigmoid used at the final layer of DeblurNet-Lite?
Answer:
Since input images are normalized to [0.0, 1.0], the output restored image must strictly conform to valid pixel boundaries [0.0, 1.0]. A Sigmoid activation mathematically squashes all output values between 0.0 and 1.0, preventing negative pixel values or values exceeding 1.0.

Q47: How does PyTorch represent image dimensions?
Answer:
PyTorch uses the (B, C, H, W) convention:
- B: Batch size (number of images)
- C: Channels (3 for RGB)
- H: Height (pixels)
- W: Width (pixels)
In contrast, libraries like OpenCV and PIL use (H, W, C). We use `TF.to_tensor()` and `TF.to_pil_image()` to convert seamlessly.

Q48: How are model weights saved and loaded in PyTorch?
Answer:
We save using `torch.save(checkpoint_dict, filepath)`, which serializes the model's `state_dict` (an OrderedDict mapping layer names to parameter tensors) using Python's pickle. We load it using `torch.load(filepath, map_location=device)` and `model.load_state_dict(...)`.

CATEGORY J: QUESTIONS ABOUT OUR PROJECT DECISIONS
--------------------------------------------------------------------------------

Q55: Why did we build a custom architecture instead of using a pretrained ResNet or VGG?
Answer:
Pretrained ResNet and VGG networks were pre-trained on ImageNet for image CLASSIFICATION (predicting category labels like "dog" or "car"). They compress spatial resolution down to 1x1 feature vectors, discarding the fine spatial coordinate information required for pixel-level image reconstruction. Our custom DeblurNet-Lite is an encoder-decoder designed specifically for dense pixel-to-pixel restoration.

Q56: Why did we choose a lightweight model over heavy SOTA models like Restormer?
Answer:
Restormer has over 26 million parameters and requires high-end GPUs with 16GB VRAM. In our project context, we had a strict constraint of local CPU training on 4 GB RAM. DeblurNet-Lite demonstrates that core deep learning restoration principles can be mastered, verified, and demonstrated on everyday hardware.

Q57: Why did we choose 3 Residual Blocks in the bottleneck?
Answer:
Empirical ablation: 1 residual block lacked sufficient non-linear depth to learn complex blur inversions; 5 residual blocks increased training time per epoch on CPU beyond our timeline. 3 residual blocks provided the optimal balance between gradient flow, expressive capacity, and CPU speed.

Q58: Why did we use Symmetric Skip Connections?
Answer:
Downsampling (stride=2 convolution) reduces spatial resolution to extract broad contextual features, but it destroys high-frequency edge locations. The skip connection directly routes the high-resolution feature map from the first layer to the decoder, restoring sharp edges during final image synthesis.

Q59: Why did we use bicubic interpolation instead of nearest neighbor or bilinear?
Answer:
Bicubic interpolation considers a 4x4 grid of 16 surrounding pixels and uses cubic splines. It produces significantly smoother surfaces with fewer interpolation artifacts than nearest neighbor or bilinear resampling.

Q60: Why did we provide a Google Colab notebook alongside local CPU training?
Answer:
To ensure dual-mode deployment: Local CPU allows fully offline execution without internet; Google Colab provides an optional zero-cost NVIDIA T4 GPU environment for training larger 256x256 patches or 50+ epochs in just 2 minutes.

CATEGORY K: TRICKY QUESTIONS PROFESSORS MIGHT ASK
--------------------------------------------------------------------------------

Q61: "Can your model deblur an image if the blur is caused by extreme high-speed motion (e.g. 100-pixel blur)?"
Answer:
No, and we explicitly document this limitation. A convolutional network can only resolve patterns within its effective receptive field. For blur kernel lengths exceeding ~20 pixels, our lightweight architecture produces a smoothed restoration rather than recovering microscopic details. Handling 100-pixel blur would require multi-scale scale-recurrent networks or transformer architectures with larger receptive fields.

Q62: "Does your model hallucinate details that were not in the original scene?"
Answer:
Because we trained using L1 pixel loss rather than an adversarial GAN loss, our model does NOT hallucinate fake details. GANs (like DeblurGAN) can generate plausible-looking fake textures (e.g., inventing fake brick lines). Our L1-trained model is conservative and mathematically faithful to the true signal.

Q63: "What happens if you feed a completely sharp image into your deblurring model?"
Answer:
Because the network learned an identity-like residual shortcut (Output = x + F(x)), when fed a sharp image, the learned residual correction F(x) is close to zero. The network passes the image through with minimal change, though slight smoothing may occur due to the Sigmoid bounding.

Q64: "Why didn't you use Batch Normalization in the residual blocks' output addition?"
Answer:
Following modern image restoration literature (such as EDSR and WDSR), Batch Normalization normalizes feature scales. In image-to-image regression, absolute pixel contrast matters. Adding BN directly after the identity sum can wash out dynamic range. We kept BN inside the residual branch but kept the identity shortcut clean.

Q65: "How do you know your model didn't just memorize the 240 training images?"
Answer:
We evaluated the model on 30 completely independent test images that were never seen during training. The test set achieved a +3.53 dB PSNR gain and +0.1975 SSIM gain, proving genuine out-of-sample generalization.

Q66: "If you had access to an NVIDIA A100 GPU, what is the single biggest change you would make?"
Answer:
We would incorporate a Perceptual Loss (calculating feature distance using pretrained VGG-19 feature layers) combined with Charbonnier Loss, and expand the architecture to a multi-stage progressive network (like MPRNet) with 256x256 patch training.

CATEGORY L: LIMITATIONS AND FUTURE IMPROVEMENTS
--------------------------------------------------------------------------------

Q67: What are the primary limitations of DeblurNet-Lite?
Answer:
1. Limited receptive field: Best suited for mild-to-moderate motion and defocus blur (7 to 15 pixel kernels).
2. Patch size: Trained on 128x128 patches; full 4K images require tiling to prevent CPU memory spikes.
3. Single image only: Does not exploit temporal correlations from adjacent video frames.

Q68: What is Perceptual Loss, and why is it a future enhancement?
Answer:
L1 and PSNR measure pixel-by-pixel intensity differences. However, human eyes care about semantic content. Perceptual Loss (Johnson et al.) computes the Euclidean distance between deep feature representations extracted by a pretrained VGG network, resulting in visually crisper textures.

Q69: How could this project be extended to video deblurring?
Answer:
Video deblurring takes advantage of temporal redundancy across neighboring frames (e.g., Frame t-1, Frame t, Frame t+1). By adding 3D convolutions or optical flow alignment modules, information from sharp adjacent frames can be warped to restore blurry middle frames.

Q70: What real-world applications benefit from lightweight image deblurring?
Answer:
1. Automatic Number Plate Recognition (ANPR) cameras capturing moving vehicles.
2. Smartphone photography in low-light night mode.
3. Handheld barcode and QR code scanners in logistics.
4. Medical endoscopy and retinal imaging where patient movement creates blur.
